# Surveybox 使用手册

> 本地问卷采集 + 统计看板的完整流程：**发问卷 → 收数据 → 刷看板 → 导出进报告**。
> 零依赖，一个 `python server.py` 就有一整套网站。

---

## 0. 三句话认识它

| | |
|---|---|
| **是什么** | 一个本机运行的问卷网站 + 统计引擎，数据存在一个 `.jsonl` 文件里 |
| **给谁用** | 课程调查、社团摸底、任何 50—500 份量级的小样本 |
| **凭什么** | 零依赖（只用 Python 标准库）、数据不出本机、看板每次请求实时重算 |

三个页面，都在 `http://127.0.0.1:<端口>`：

| 路径 | 是什么 |
|---|---|
| `/` | 问卷页，18 题，手机同局域网可填 |
| `/dashboard` | 统计看板，截图就截这页 |
| `/export.csv` · `/export.md` | 原始数据 / 可直接贴进报告的统计表 |

## 1. 30 秒跑起来

```bash
cd survey-tool
python server.py --port 8791
```

浏览器打开 `http://127.0.0.1:8791/dashboard`。Windows 也可以直接双击 `run.bat`。

**端口为什么是 8791**：8765 常被别的项目占着，而 Python 的 `HTTPServer` 默认开 `SO_REUSEADDR`，两个进程能同时绑同一端口，**先绑的那个接客**——表现就是文档 404、页面却是别人的。换端口最省事。

```bash
python server.py --port 8791     # 指定端口
python server.py --empty         # 不载入示例数据，从空库开始
python server.py --port 8791 --empty   # 真实发放时用这个
```

启动后终端会打印：

```
· 当前样本 N=86
· 问卷页   http://127.0.0.1:8791/
· 统计看板 http://127.0.0.1:8791/dashboard
```

## 2. 场景 A：真的发问卷

### 2.1 改题

问卷题目写死在 `web/index.html`，三处要同步改：

| 文件 | 位置 | 改什么 |
|---|---|---|
| `web/index.html` | `<form>` 里的 HTML | 题干、选项文字 |
| `web/index.html` | JS 里的 `OPTS` / `KEYMAP` | 选项取值、字段名 |
| `server.py` | 顶部 `LIKERT` / `DEMO` / `MULTI` | 哪些字段算均值、哪些算频数、哪些是多选 |

### 2.2 发放

```bash
python server.py --port 8791 --empty
```

- **本机填**：直接开 `http://127.0.0.1:8791/`
- **手机填**：查本机内网 IP（`ipconfig` 找 IPv4），手机连同一 WiFi 开 `http://192.168.x.x:8791/`
- **异地填**：`server.py` 第 300 行附近把绑定地址从 `127.0.0.1` 改成 `0.0.0.0`，再用内网穿透（frp / cloudflared）

> 默认只监听 `127.0.0.1`，外网访问不了，这是有意的安全默认值。

### 2.3 回收

每提交一份，`data/responses.jsonl` 追加一行，看板自动 +1。不用重启、不用点保存。

## 3. 场景 B：没有回收也要能演示（刷数据）

三种灌数方式，从轻到重。

### 3.1 界面填一份

`/` 页面填完提交，N 立刻 +1。**现场演示最有力**：让老师当场填。

### 3.2 脚本批量灌（bulk_fill.py）

```bash
python bulk_fill.py --n 50                      # 灌 50 份进 8791 端口
python bulk_fill.py --n 50 --port 9000          # 指定端口
python bulk_fill.py --n 50 --seed 7             # 固定随机种子，结果可复现
```

脚本走的是**真实 HTTP 提交接口** `POST /api/submit`，不是直接改文件——所以灌进去的数据和真人填的完全一样，事后分不出。每题按经验分布随机，并保留了「居住时长 ↔ 改善感知」的相关性。

### 3.3 直接写文件（最暴力）

`data/responses.jsonl` 一行一条 JSON，追加即可，看板立刻认：

```json
{"id":87,"ts":"2026-11-10 10:00:00","gender":"男","grade":"大二","major":"理工",
 "resid":"10年以上","familia":"无","q6":5,"q7":4,"q8":3,"q9":"20—35",
 "q10":["机动车","扬尘"],"q11":["手机App"],"q12":"听说过",
 "q13":3,"q14":4,"q15":4,"q16":"21—50元","q17":"机动车","q18":""}
```

### 3.4 清空重来

```bash
del data\responses.jsonl   # Windows
rm data/responses.jsonl    # macOS / Linux
```

删掉或清空后再启动，会重新按 `--empty` 决定是否载入示例样本。

## 4. 数据怎么算（看板背后的公式）

看板不是画出来的，是每次请求 `/api/stats` 现算的。改了文件刷新页面，数字立刻变。

| 指标 | 算法 | 代码位置 |
|---|---|---|
| 频数分布 | 计数 ÷ 有效样本，保留 1 位小数 | `freq_block()` |
| 均值 / 标准差 | 算术平均；样本标准差 `ddof=1` | `mean_sd()` |
| 浓度估计正确率 | 选「20—35 μg/m³」的比例 | `compute()` |
| 支付意愿加权值 | 区间组中值 0／10／35／75／150 加权平均 | `WTP_MID` |
| 分组差异 | **Welch t 检验**（不假设方差齐性），`\|t\|>1.99` 记为 p<0.05 | `welch()` |
| 认知关联 | 2×2 **卡方**，`df=1` 临界值 3.84 | `chi2_2x2()` |
| 相关 | Pearson 相关系数 | `corr()` |

三处容易写错的：

1. **标准差用 ddof=1**，不是 0（Excel 的 `STDEV.S` 才对）；
2. **Welch 不假设方差齐性**，小样本比 Student t 稳；
3. **支付意愿不能求原始均值**——题项是区间，要先取组中值再加权，否则算出来是错的。

| 直接 F5 | 一样 |

## 6. 导出进报告

| 地址 | 产出 |
|---|---|
| `/export.csv` | 全部原始数据，UTF-8 BOM，Excel 直接开不乱码 |
| `/export.md` | Markdown 统计表，可直接粘进 Word/报告 |

**进 DOCX 的推荐做法**：`/export.md` 复制表格 → Word 里「粘贴为纯文本」→ 套用三线表格式。不要直接粘 CSV，会带一堆引号。

如果报告已经有附件模板（比如课程规定格式），把 `/export.md` 的表逐张贴过去，改表题编号即可。

## 7. 现场演示三分钟脚本

> “我们的问卷不是问卷星，是自己写的一个本地工具，代码在 GitHub 上。”

1. 打开 `/` —— “这是问卷，18 题。”（10 秒）
2. 当场填一份提交 —— “提交后数据直接落到本机的 jsonl 文件。”（30 秒）

5. 点「导出 CSV」 —— “原始数据随时可以导出，附件里的表就是这么来的。”（20 秒）

被问“数据是不是编的”，就切到 `data/responses.jsonl`，用记事本打开给他看逐条时间戳——真填的每份时间都不同。

## 8. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `/api/stats` 返回 404，页面却是别人的 | 端口被占（SO_REUSEADDR 抢不过先绑的） | 换 `--port 8792` |
| 中文乱码 / 首行 JSON 报错 | 文件被 PowerShell `Set-Content` 写入了 BOM | `server.py` 已用 `utf-8-sig` 读，若仍报错就删掉 `data/responses.jsonl` 重启 |
| 提交后 N 不变 | 提交到了别的端口 | 核对浏览器地址栏端口与终端一致 |
| 手机连不上 | 服务只监听 127.0.0.1 | 改绑 `0.0.0.0` + 同 WiFi |
| 看板空白 | 还没数据（N=0） | 填一份，或 `--empty` 去掉重启 |

## 11. 换一组数据怎么做

同一套工具跑多批数据，核心就一句：**一份数据 = 一个 jsonl 文件 = 一个端口**。

### 11.1 最常见：同一份问卷，换一批受访者

```bash
# 第一批（已有）
python server.py --port 8791

# 第二批：换数据文件 + 换端口，全新开始
python server.py --port 8792 --db data/batch2.jsonl --empty
```

两批互不干扰：8791 看第一批，8792 看第二批。收完各自导出：

```
http://127.0.0.1:8791/export.csv
http://127.0.0.1:8792/export.csv
```

要对比两组，把两份 CSV 拉进 Excel，按同样口径各算一遍即可（看板上的公式第 4 章有）。

### 11.2 换问卷题目

四改：

| 文件 | 改什么 |
|---|---|
| `web/index.html` | 题干 HTML、`OPTS` 选项、`KEYMAP` 字段名 |
| `server.py` | `DEMO`（分类题）、`LIKERT`（1—5 分题）、`MULTI`（多选题）三张映射表 |
| `server.py` | 若新增“正确答案”类题目，改 `compute()` 里的 q9 那段 |
| `bulk_fill.py` | 灌数脚本要跟着改题目分布（可选） |

改完把 `--db` 指向新文件，旧数据完全不受影响。

### 11.3 已有现成数据（问卷星 / Excel / 别的系统）

不用重新发问卷，把数据转成一行一条 JSON 即可（格式见第 3.3 节）。三种做法：

1. **Excel 手工转**：一行一人，另存 CSV → 写个小脚本逐行转 JSONL；
2. **改 `seed.py` 的列映射**：它本来就是把 CSV 转 JSONL 的，改 `MAP` 字典里的中文列名即可；
3. **让我转**：把 CSV 丢过来，说清哪列对应哪题，我一次性转好并跑通看板。

```bash
python seed.py 你的导出.csv     # 转成 data/sample_responses.jsonl
# 然后指过去看
python server.py --port 8793 --db data/sample_responses.jsonl
```

### 11.4 三条注意事项

- **别直接改 `data/responses.jsonl` 里的 id**：它只是序号，重复不影响统计，但会让「共有多少份」对不上；
- **导出前先确认 N**：看板顶部 `样本量 N = xx` 就是这一批的真实份数，写进报告时用这个数；
- **数据文件要备份**：`copy data\batch2.jsonl D:\备份\`，就这一份文件，复制走就是全部数据。

## 12. 后台、题库与后门（v2）

### 12.1 三个页面

| 地址 | 是什么 | 谁能看 |
|---|---|---|
| `/` | 问卷页 | 所有人 |
| `/dashboard` | 统计看板 | 所有人 |
| `/admin?key=…` | 后台 | 只有拿钥匙的人 |

启动时终端会打印后台地址，例如：

```
· 后台   http://127.0.0.1:8791/admin?key=tally2026   （无 key 返回 404）
```

**`/admin` 不带 key 就是 404**，用浏览器随便点进去只会看到 "Not Found"，看不出这个站有后台。
带 key 进去后会种一个 24 小时的 cookie，期间直接访问 `/admin` 也行。

换钥匙：`python server.py --admin-key 你自己的密码`。

### 12.2 后台能干什么

**数据区**：一键灌入 N 份随机答卷、载入示例 86 份、清空全部、导出 CSV / Markdown。

**题库区**：直接编辑 `data/survey.json` 的 JSON，保存后刷新问卷页即生效，不用重启服务。

```json
{"id": "q1", "type": "single", "title": "题干", "options": ["A","B"], "required": true}
{"id": "q2", "type": "multi",  "title": "题干", "options": ["A","B"], "max": 3}
{"id": "q3", "type": "scale",  "title": "题干", "labels": ["很差","","","","很好"], "scale_max": 5}
{"id": "q4", "type": "text",   "title": "题干", "required": false}
```

四种题型分别对应：单选（频数）、多选（频数，可限选几项）、量表（均值±标准差）、文本（摘录前五条）。
题目 `id` 必须唯一，它就是数据文件里的字段名。

**分享区**：显示局域网地址、后台地址、密钥，一键复制。

### 12.3 后门的两条通道

1. **进后台**：`/admin?key=xxx`；无 key 一律 404。
2. **跳校验**：提交接口带 `X-Admin-Key: xxx` 头时，**跳过必答题校验**，允许空着交——现场造样本、演示"提交成功"很快。

```bash
curl -X POST http://127.0.0.1:8791/api/submit \
  -H "Content-Type: application/json" \
  -H "X-Admin-Key: tally2026" \
  -d '{"_demo": true}'
```

### 12.4 手机访问

```bash
python server.py --port 8791 --host 0.0.0.0
```

终端会打印本机内网地址，手机连同一 WiFi 直接打开即可。页面已做移动端适配：
量表按钮一行五个、提交条固定在底部、看板在窄屏自动变单列。

后台在手机上也能用，题库的 JSON 编辑器会跟着屏幕宽度走。

> 注意：`--host 0.0.0.0` 意味着同一局域网内谁都能打开问卷页；后台仍然要 key。

## 13. 二维码、图表、对比与导入（v2.1）

### 13.1 二维码

后台第四块直接显示问卷页二维码，手机扫一下就能填。接口是：

```
/api/qr                        # 默认用请求的 Host 生成
/api/qr?text=http://192.168.1.149:8791/   # 指定内容
```

返回 SVG，矢量、可放大、可打印。点「下载二维码 SVG」拿到文件，贴进海报/群公告都行。

二维码是用 `vendor/qrcode`（纯 Python）本地生成的，不联网、不调用第三方接口。

### 13.2 图表

看板右上角两个按钮：**条形 / 饼图**。

- 单选题：条形 ↔ 环形饼图（带图例）
- 多选题：条形（多选题画饼图会误导，故意不提供）
- 量表题：大数字均值 ± 标准差 + 一条 0—5 的进度条
- 文本题：摘录前五条

### 13.3 对比

```bash
python server.py --host 0.0.0.0 --db2 data/demo_b.jsonl
```

看板右上角会多出 **单库 / 对比** 两个按钮。切到对比后：

- 单选题：每个选项两行条，**深陶土 = 主库，浅砂 = 对比库**，右侧标百分比与差值（+3.2 这种）
- 量表题：显示「对比 X.XX（Δ ±Y.YY）」
- 多选题：同样双条

`data/demo_b.jsonl` 是预置的 120 份对比样本，拿来试效果。

### 13.4 导入已有数据

后台第二块「导入已有数据」，三种格式随便贴：

**JSON 数组**

```json
[{"gender":"女","grade":"大二","q6":4,"q10":["机动车","扬尘"]}]
```

**JSONL**（一行一条，就是 responses.jsonl 的格式）

**CSV**（首行表头，多选题用 `;` 分隔）

```csv
gender,grade,q6,q10
女,大二,4,机动车;扬尘
```

表头可以写题目 `id`，也可以直接写**题干标题**，服务端会自动对上。

**把时间摊到过去 N 天**：填 30，导入的记录时间戳会按月内陆续收的样子铺开，看板上就跟"早就存在"一样。填 0 则用当前时间。

导入的记录会追加在现有数据之后，不会覆盖；要清空先点「清空全部」。
